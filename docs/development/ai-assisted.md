# 开发方式与贡献说明

> 这份文档说明我在这个项目里怎么用 AI、哪些是我负责的，避免“代码到底是谁写的”说不清。

## 1. 结论

这个项目我采用了 **AI 辅助开发**，不隐藏 AI 参与。

准确说：

> **AI 帮我出初稿、样板和重复性实现；我负责架构约束、接口取舍、代码审查、硬件测试、修改决策和文档验收。**

不是“AI 全自动生成”，也不是“我逐行手写”。

## 2. 我的背景

我是新生，课程主线是 **C++**，不是 C。

所以：

- C++ 的类、接口、模板、`enum class`、`[[nodiscard]]` 对我来说不是主要障碍；
- C 的嵌入式写法（指针、`volatile`、中断、链接脚本、HAL）是我在项目里边做边补的；
- 我能阅读并修改 `board/`、`bsp/stm32/` 的 C 代码；
- 我能定位编译、链接、启动和串口问题；
- 复杂外设的初稿我会借助 AI，但关键路径我会审查、烧录、实测。

这不是“C 语言差”，而是 **C++ 课程背景 + 嵌入式 C 工程经验少**。两件事要分开看。

## 3. AI 帮我做什么

- 生成初稿、样板代码、重复性适配代码；
- 提供调试思路、编译/链接错误排查建议；
- 生成文档草稿、表格和排版草稿；
- 在我给定接口和约束后，补全实现细节。

## 4. 我负责什么

- 需求拆解与验收标准；
- 分层方向与接口边界（BSP / interface / adapter / board）；
- 硬件选型、接线、烧录、串口测试；
- 代码审查与修改决策；
- 测试记录、文档校对、未完成项标注；
- 判断“哪些能写完成、哪些只能写限制”。

## 6. 我能讲清什么

我至少能讲清：

- UART 从 `app` 到 `HAL_UART_Transmit` 的调用链；
- 为什么 UART 只保留阻塞 + 中断，不假装支持 DMA；
- 六任务的优先级、周期、栈和 IPC 选择；
- 为什么 IMU 用单槽队列、日志用 drop-new；
- 为什么 CRC 错要返回 `Checksum`，而不是静默丢帧；
- 为什么通信超时也要让控制回零；
- 为什么 F407 的 J-Link 必须接 3V 参考；
- 为什么 MPU6500 的 `WHO_AM_I=0x70`，不能写 MPU6050。

## 7. 边界与后续

- 我不把“AI 生成”说成“我手写”；
- 我不把“没通过”说成“已实现”；
- 我不把“预留接口”说成“已使用”；
- 后续我要补：指针/`volatile`/链接脚本/ISR 的独立编写能力，以及单元测试和 HIL。

## 8. 一句话

> **AI 是实现助手，我是 AI Driver：定架构、做审查、跑测试、对结果负责。**
